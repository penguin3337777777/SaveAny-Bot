# 按标签收集历史视频

```text
/collect @群组用户名 --tag "#教程"
```

需要启用并登录现有的 UserBot。登录账号必须能访问目标群组/频道及相关历史消息；Bot Token 本身不能读取群组历史。私有群可使用账号已知的聊天 ID（必要时先执行 `/syncpeers`）。也接受 `https://t.me/群组用户名`；不接受邀请链接或消息链接。

命令直接排队执行，不弹存储选择或覆盖确认，包括 silent 模式。未开启 silent 时也采用相同的无确认流程。没有默认存储时会提示先通过现有 `/storage` 设置。

可选参数：

- `--type video`：默认 video，当前仅支持视频（也识别作为文件发送的视频）。
- `--storage 名称`：默认使用当前用户的默认存储。默认目录仅在属于该存储时复用。

沿用现有文件命名设置和已启用的 `/rule`。`CHOSEN` 表示命令选定的存储；`NEW-FOR-ALBUM` 使用该组最早视频的文件名作为目录名。最终路径包含存储 `base_path`，不另增配置字段。

## 检索和去重

分页从新到旧扫描账号可见的历史消息，而非只依赖 Telegram 搜索索引，检查消息正文/说明中的完整标签（忽略大小写）。`#教程` 不匹配 `#教程推荐`。连续媒体组任一成员带标签时，保存组内的视频；跨分页的媒体组也会合并。不因邻近的独立文字消息带标签而保存其他消息。

先完成整个历史范围的扫描，再开始查重和保存。扫描阶段不下载视频；“匹配视频”在扫描结束后固定为本次候选总数，其中可能包含之后同名跳过的文件。正常结束时，保存成功、同名跳过、失败三项之和等于该总数。扫描失败或取消时，不执行任何保存。

第一批消息限定本次历史范围；执行期间新增的消息留到下一次。保存阶段按扫描记录的消息编号重新读取源消息，不再重新匹配标签；源消息或所需媒体组成员被删除、媒体组改变时计入失败，文件名和存储规则使用重新读取的当前消息信息。相同目标文件名由先取得该路径锁的文件保存，其余再次查重后跳过。并行模式下不保证同名文件的先后顺序。

下载之前，检查最终存储、目录、文件名；同名存在则跳过，不下载、不上传、不自动改名。上传前再检查一次。并行收集任务按目标路径协调，避免同时处理同一目标。此操作并非与外部上传程序之间的原子事务。

当前可靠查重支持 **AList/OpenList 与本地存储**。其他后端或规则跳转到不支持的后端会明确失败，不将不确定状态当作不存在。检查超时、权限错误、后端错误会有限重试；仍失败则跳过下载并计入失败。内容不同但同名仍会跳过；同内容但改了文件名不属于同名去重。

## 资源与恢复

每个收集任务复用现有任务队列，并按现有 `workers` 设置并行处理文件。`workers=2` 时，单条命令最多同时处理两个视频；多个 `/collect` 共用两个文件处理名额，不因命令数量增加而翻倍。普通保存任务仍使用原有队列，并不共享此采集专用文件限制。

扫描阶段在内存中保存紧凑的消息编号、媒体组编号和视频标记，不保留全部消息正文、文件元数据或视频内容。清单最多包含 100,000 条关联消息（包括匹配媒体组中的非视频成员），达到上限后继续遇到匹配项会在下载之前报错停止，避免小内存服务器无限积累。其余仅保留一页（最多 100 条）、一个媒体组（最多 10 条）、有限的正在处理文件、计数和最近一条错误。清单随任务结束释放，不写入磁盘；没有新数据库、进度文件或持久化任务清单。

下载沿用原有临时文件，并在成功、异常或取消后执行关闭删除。正常日志仍受现有日志设置管理；不为每条扫描/同名跳过写入日志。系统 Swap 和原有 Telegram 会话管理不属于新增任务状态。

进度消息的布局保持不变，标题区分“正在扫描”和“扫描完成，正在保存”；全部实际保存成功时显示“保存完成，全部成功”，存在同名跳过时单独说明，有失败或取消时不会显示全部成功。没有匹配项时显示“扫描完成，没有匹配的视频”。同一条进度消息显示总计及各个当前文件的文件名、阶段、进度条、已传输大小和阶段平均速率。`workers=2` 时最多显示两条文件进度；大并发设置最多展开四条，其余显示数量。下载、传至存储接口、等待存储完成分别显示。上传速率只表示 Bot 向存储接口传输的速率，不表示 OpenList 向 115 的实际网络速度；进度达到 100% 后仍可能等待 OpenList 完成网盘上传，只有存储返回成功才计入保存成功。重试会重置当前上传进度，完成行及时移除。

进度消息受现有更新间隔限制。可以点击取消或 `/cancel 任务ID`；取消停止扫描和当前传输。Bot 重启后不恢复此任务，重新发送命令会重新扫描，并依据远端当前文件跳过同名项。修改命名策略、规则或目录后，最终路径变化，去重结果也会变化。

这是 Telegram 命令功能；HTTP API 不接受 `collect`，以免缺少用户权限和默认设置上下文。
